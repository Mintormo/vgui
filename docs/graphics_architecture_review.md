# Анализ архитектуры отрисовки vgui

## Общий подход

Стек: **SDL2 Renderer (аппаратный 2D) + SDL2_ttf + SDL2_gfx**. Каждый кадр — immediate-mode обход дерева виджетов, каждый виджет вызывает `ctx.fill_rect`/`ctx.draw_text`/etc., которые транслируются в `SDL_RenderFillRect`, `SDL_RenderCopy` и т.п. Презентация через `SDL_RenderPresent` с включённым VSync ([sdl2_window.v:149-150](../vgui/sdl2_window.v#L149-L150)).

Подход адекватный для классического desktop-GUI: это та же модель, что у Dear ImGui, Nuklear, raylib-GUI. Для типичного приложения с десятками-сотнями виджетов это не упирается ни в CPU, ни в GPU.

## Что сделано хорошо

1. **Event-driven с `SDL_WaitEventTimeout`** ([sdl2_app.v:127-129](../vgui/sdl2_app.v#L127-L129)). Без событий цикл спит до 100мс — приложение не жжёт CPU простаивая. При активной анимации таймаут падает до 33мс. Это правильная модель для GUI (не игровой движок — не надо рендерить 60 раз в секунду статичный экран).
2. **Кэш текстур текста** в [sdl2_fonts.v:225-265](../vgui/sdl2_fonts.v#L225-L265). Ключ `text|size|style|color`, `TTF_RenderUTF8_Blended` → `SDL_Texture` один раз, потом дешёвый `SDL_RenderCopy`. Это критично — рендер шрифтов в TTF дорогой.
3. **Clipping-стек** ([sdl2_render.v:9-41](../vgui/sdl2_render.v#L9-L41)) с пересечением — корректная семантика для вложенных контейнеров.
4. **Fast-path для `WINDOWEVENT_EXPOSED`** ([sdl2_app.v:151-167](../vgui/sdl2_app.v#L151-L167)) — мгновенная перерисовка при resize без мерцания.
5. **Разделение бекенда** ([render_context.v](../vgui/render_context.v) — структура, [sdl2_render.v](../vgui/sdl2_render.v) / [sdl2_fonts.v](../vgui/sdl2_fonts.v) — реализация). Можно теоретически прикрутить другой бекенд.

## Архитектурные проблемы

### 1. `render_all()` рендерит ВСЕ окна каждый кадр, без dirty-check ✅ ИСПРАВЛЕНО

[sdl2_app.v:913-922](../vgui/sdl2_app.v#L913-L922): `render_all()` безусловно перерисовывает каждое окно после `process_events()`. Учитывая, что `process_events` уже вернул `true/false` (был ли событие), но возвращаемое значение **игнорируется** ([sdl2_app.v:88-91](../vgui/sdl2_app.v#L88-L91)). То есть даже на пустом таймауте без анимаций — полная перерисовка всех окон. Это убивает идею event-driven цикла, на которую рассчитан `WaitEventTimeout`.

**Что должно быть**: `if events_processed || any_anim || expose_pending: render_all()`. Сейчас имеется поле `anim_until` — но оно не используется, мёртвый код.

**Фикс**: `run()` теперь делает один начальный `render_all()`, а в основном цикле вызывает его только если `process_events` обработал событие или какое-либо окно/диалог установило `needs_animation` в прошлом кадре ([sdl2_app.v:87-124](../vgui/sdl2_app.v#L87-L124)). Expose-события рендерятся fast-path внутри `process_events` отдельно. Idle CPU теперь близок к нулю — цикл блокируется на `SDL_WaitEventTimeout(100ms)` без перерисовки.

### 2. `fill_pill_rect` создаёт и уничтожает текстуру на каждом кадре ✅ ИСПРАВЛЕНО

[sdl2_render.v:120-184](../vgui/sdl2_render.v#L120-L184): supersampled-pill (3× больше + downsampling). На каждый вызов — `SDL_CreateTexture` + `SDL_RenderClear` + `roundedBoxRGBA` + `SDL_RenderCopy` + `SDL_DestroyTexture`. Если это рисуется на каждом кадре (например, толстый pill-progress bar или pill-кнопка с hover-анимацией), это серьёзный hit: создание VRAM-текстуры 3× размера + дорогая `roundedBoxRGBA` каждый кадр.

**Фикс**: добавлен `pill_cache map[string]PillCacheEntry` в `RenderContext` с лимитом 256 записей. Ключ — `"w|h|rad_q|r,g,b,a"`, где `rad_q` квантован с шагом 0.5px (чтобы флоатовый дрейф не порождал дубликаты). При попадании в кэш — только `SDL_RenderCopy`, без аллокации текстуры. При промахе текстура создаётся и кладётся в кэш (без `SDL_DestroyTexture` в конце). Эвикция LRU ~25% при переполнении — та же модель, что у `evict_text_cache_lru`. Кэш сбрасывается при смене темы, изменении масштаба/шрифта и при разрушении контекста (`cleanup_fonts`).

### 3. Кэш текста сбрасывается полностью при переполнении ✅ ИСПРАВЛЕНО

[sdl2_fonts.v:258-260](../vgui/sdl2_fonts.v#L258-L260): при достижении `cache_max=256` весь кэш `clear_text_cache()` — все текстуры уничтожаются. На приложении с большим списком (например, `ListBox` с 1000 строк, `CodeEditor`, `TableView`) это означает хроническую thrash-проблему: каждый кадр кэш переполняется, очищается, заполняется заново. Нужен LRU и/или адекватный лимит (а лучше — весовой по сумме `w*h*4` байт).

**Фикс**: в `TextCacheEntry` добавлено поле `last_used: u64`, в `RenderContext` — монотонный счётчик `cache_tick`, инкрементируемый при каждом обращении. Лимит `cache_max` поднят с 256 до 1024. При переполнении вместо полного сброса вызывается `evict_text_cache_lru()` — выбрасывает ~25% записей с наименьшим `last_used` (sort + cutoff по 25-му перцентилю). Иконки (ключи с префиксом `icon:`) исключены из эвикции, так как переиспользуются и дороги в перерасчёте (диск I/O + декодирование PNG).

### 4. Линейный поиск стиля шрифта по указателю ✅ ИСПРАВЛЕНО

[sdl2_fonts.v:197-223](../vgui/sdl2_fonts.v#L197-L223): чтобы определить `style_int` для ключа кэша, делается цепочка `if font == ctx.fonts.regular ... else for k,v in size_cache`. На каждый `draw_text_with_font` — потенциально проход по всему `size_cache`. Это в hot-path. Стиль/размер должны передаваться явно или храниться в `FontHandle{font, style, size}` структуре.

**Фикс**: добавлена структура `FontHandleInfo{style_int, font_size}` и обратный map `FontSet.handle_map map[voidptr]FontHandleInfo`. Заполняется в `init_fonts` для 6 базовых шрифтов, и при каждом добавлении нового шрифта в `size_cache` внутри `get_font`. В `draw_text_with_font` вся цепочка `if/else for` заменена на O(1) lookup: `info := ctx.fonts.handle_map[font] or { FontHandleInfo{99, ctx.fonts.size} }`. Очищается вместе с `size_cache` в `cleanup_fonts`.

### 5. Нет occlusion / view-culling ✅ ИСПРАВЛЕНО

[sdl2_window.v:373-378](../vgui/sdl2_window.v#L373-L378): обходится всё дерево виджетов. `is_in_clip` существует ([render_context.v:202-208](../vgui/render_context.v#L202-L208)), но **виджеты должны вызывать его сами**, и далеко не все это делают. В скроллящихся контейнерах (`ListBox`, `TableView`, `CodeEditor`) внеэкранные строки в идеале должны skip'аться на уровне обхода, а не на уровне `SDL_RenderCopy` (SDL отбросит, но измерения текста и логика всё равно отработают).

**Фикс**: добавлен ранний выход `if !ctx.is_in_clip(x.bounds) { return }` в начало `draw()` всех виджетов — сразу после проверки `!visible`. Охват: `Label`, `Button`, `CheckBox`, `ToggleSwitch`, `RadioButton`, `Slider`, `ProgressBar`, `Spinner`, `Separator`, `TextInput`, `Spinbox`, `ComboBox`, `ImageView`, `DatePicker`, `ColorPicker`, `PlotView`, `Breadcrumbs`, `TabBox`, `Accordion`, `MenuButton`, `CodeEditor`, `MarkdownView`, `ListBox`, `TableView`, `TreeView`, `PropertyGrid` — 26 виджетов. Виджеты-оверлеи (`Tooltip`, `Notification`, `ContextMenu`, `MenuBar`) и layout-контейнеры (`VBox`, `HBox`, `Panel`, `ScrollBox`) не трогались — они всегда видимы или сами управляют clip. В scroll-виджетах (`ListBox`, `TableView`, `CodeEditor`, `TreeView`, `MarkdownView`, `PropertyGrid`) построчный culling уже существовал; guard на уровне `draw()` добавляет защиту от случая, когда весь виджет целиком за пределами viewport родителя. Для анимационных виджетов (`Spinner`, `ProgressBar`, `CodeEditor`) вложенные проверки `ctx.is_in_clip` заменены безусловным кодом — ранний выход уже гарантирует видимость.

### 6. Ключ кэша текста включает full text ✅ ИСПРАВЛЕНО

[sdl2_fonts.v:225](../vgui/sdl2_fonts.v#L225): `key := '${text}|${font_size}|${style_int}|${c.r},${c.g},${c.b},${c.a}'`. Для длинных строк (markdown, code-editor, label) каждое обращение — конкатенация и хэш длинной строки. Плюс при 256 уникальных длинных текстах кэш съест прилично RAM. Альтернатива — хэшировать в `u64` или кэшировать на уровне глифов (но это уже atlas, большой рефакторинг).

**Фикс**: добавлена функция `text_cache_key(text, font_size, style_int, c Color) u64` — FNV-1a хэш всех четырёх компонентов без строковой аллокации. Тип `text_cache` изменён с `map[string]TextCacheEntry` на `map[u64]TextCacheEntry`. Иконки вынесены из `text_cache` в отдельный `icon_cache map[string]voidptr` — их ключи коротки (пути к файлам), а сам `icon_cache` не подлежит LRU-эвикции. `evict_text_cache_lru()` упрощён — больше нет защиты `starts_with('icon:')`. `clear_text_cache()` теперь также очищает `icon_cache`. Вероятность коллизии FNV-1a: ~1/2^64 — пренебрежимо мала для GUI.

### 7. Полная очистка экрана + полная перерисовка каждый кадр

Нет concept'а dirty-rect. Это нормально для аппаратного 2D и небольших окон, но при больших окнах (4K HiDPI) и сложном UI это значимая нагрузка. Для текущего проекта вряд ли проблема, но стоит держать в уме. Реализация dirty-rect на SDL2 требует offscreen backing texture на каждое окно — серьёзный рефакторинг без ощутимой выгоды при текущем объёме UI.

### 8. `roundedBoxRGBA` из SDL2_gfx — software-рендеринг в RAM ✅ ЗАКРЫТО КЭШЕМ

SDL2_gfx рисует на CPU и заливает текстуру. Для каждой rounded-кнопки на каждом кадре — пиксельный fill в CPU. Это медленнее, чем нативный `SDL_RenderFillRect`. Проблема закрыта `pill_cache` (см. #2): `roundedBoxRGBA` вызывается только при промахе кэша, при попадании — только `SDL_RenderCopy`.

### 9. UI scale делается через post-scale текстуры, не через render-scale ✅ НЕ ПРОБЛЕМА

[sdl2_fonts.v:268-277](../vgui/sdl2_fonts.v#L268-L277): шрифт открывается на укрупнённом размере, текстура потом ужимается через `SDL_RenderCopy` с маленьким dst. Предложение использовать `SDL_RenderSetLogicalSize` неприменимо — эта функция добавляет letterboxing и рассчитана на игры с фиксированным виртуальным разрешением, не для resizable GUI. `SDL_RenderSetScale` уже используется в `set_ui_scale` ([sdl2_window.v:697](../vgui/sdl2_window.v#L697)) и `init_hidpi` ([sdl2_hdpi.v:62](../vgui/sdl2_hdpi.v#L62)) — это и есть правильный подход для SDL2 HiDPI GUI. Текущая архитектура (RenderSetScale + шрифты на физическом размере + деление в measure/draw) корректна и идиоматична.

## Обзор #2 (май 2026)

Повторный анализ после исправления проблем #1–6.

### 10. Мёртвый код в `App` — три неиспользуемые сущности

[sdl2_app.v:33](../vgui/sdl2_app.v#L33) — поле `anim_until u32` в структуре `App`. Осталось от ранней реализации анимационного таймера; сейчас анимация управляется через `ctx.needs_animation` в каждом окне. Поле занимает место в структуре и вводит читателя в заблуждение.

[sdl2_app.v:64-80](../vgui/sdl2_app.v#L64-L80) — функция `find_ctx_for_window(wid u32)`. Нигде не вызывается — поиск по всей кодовой базе подтверждён. Логика дублирует inline-поиск внутри `process_events`.

[sdl2_app.v:481-490](../vgui/sdl2_app.v#L481-L490) — функция `reset_all_pressed()`. Нигде не вызывается. Сбрасывает флаг `pressed` у всех кнопок через `focus.entries` — O(n) по всем виджетам.

**Влияние**: минор — мёртвый код, не вредит, но замусоривает.
**Решение**: удалить все три.

### 11. Логика modal-диалога берёт последний открытый, а не первый

[sdl2_app.v:201-205](../vgui/sdl2_app.v#L201-L205):
```v
mut modal_dialog := unsafe { &Dialog(nil) }
for mut d in app.dialogs {
    if d.is_open() && d.modal {
        modal_dialog = unsafe { d }  // перезапись — активен последний в списке
    }
}
```
Если одновременно открыто несколько modal-диалогов (теоретически возможно), активным будет последний добавленный в `app.dialogs`, а не первый открытый. На практике это не проявляется, потому что приложения обычно открывают один modal за раз — но семантика должна быть "самый последний открытый" (стек), а не "последний в списке регистрации".

**Влияние**: минор в текущих приложениях; потенциально значим при вложенных диалогах (например, диалог открывает второй диалог-подтверждение).
**Решение**: инвертировать обход: `for i := app.dialogs.len - 1; i >= 0; i--` и взять первый подходящий — это даст "последний открытый" семантику стека.

### 12. `set_widget_bounds` вызывается каждый кадр без проверки изменений

[sdl2_window.v:374-378](../vgui/sdl2_window.v#L374-L378): на каждый вызов `render()` — `set_widget_bounds` для всех корневых виджетов, независимо от того, изменился ли размер окна. `set_widget_bounds` рекурсивно обходит всё дерево и пересчитывает `bounds` у каждого виджета. Для простого окна с 50 виджетами это ~50 операций структуры `Rect` каждый кадр без смысла.

**Влияние**: минор — константный overhead, не асимптотический; при глубоком дереве (100+ виджетов) становится заметнее.
**Решение**: добавить поля `last_layout_w f32` / `last_layout_h f32` в `Window`; вызывать `set_widget_bounds` только если `screen_width != last_layout_w || screen_height != last_layout_h`.

### 13. `FocusManager.register_ptr` — O(n) поиск дубликатов

[focus.v:33-44](../vgui/focus.v#L33-L44): при каждой регистрации виджета линейный проход по `entries` для поиска дубликата. Вызывается один раз при инициализации каждого виджета (не в per-frame hot-path), поэтому для окна со 100 виджетами — 100×50=5000 сравнений при старте. Не критично, но легко устраняется.

**Влияние**: минор — только при инициализации, не при рендере.
**Решение**: добавить `registered map[voidptr]bool` в `FocusManager`; проверка и вставка за O(1).

## Вердикт

Подход **разумный и идиоматичный для SDL2-based GUI**, не overengineered. Для приложений с обычной нагрузкой (десятки-сотни виджетов, нечастые перерисовки) — летает.
