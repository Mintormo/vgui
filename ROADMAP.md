# ROADMAP — что отделяет vgui от «больших» GUI-библиотек

Набор виджетов в vgui уже близок к Qt Widgets (около 50 типов виджетов:
таблица, дерево, редактор кода с минимапой, markdown-view, property grid,
графики, редактор кривой, календарь, холст; плюс трей и стек отмены). Отставание — не в количестве виджетов, а в инфраструктуре.

Список отсортирован по приоритету.

План общий для всех трёх проектов: библиотеки vgui, C-ABI-моста `../vgui-capi` и
Python-обёртки `../vguipy`. Пункты «пробросить в C-ABI / Python» делаются в них.

Здесь — крупные направления развития. Конкретные найденные ошибки и
утечки (с замерами, ссылками на строки и планом починки) вынесены
отдельно: [docs/audit_2026_09.md](docs/audit_2026_09.md).
Наблюдения прохода комментариев (октябрь 2026, все три проекта, закрыты
полностью 13.10.2026): [docs/audit_2026_10.md](docs/audit_2026_10.md).

## 1. Layout-система (measure/arrange) — ГЛАВНОЕ

**Статус:** ✅ сделано (ветка `layout-system`, влита в master)

Было: интерфейс `Widget` состоял из `draw` + `handle_event`, фазы измерения
не существовало. `preferred_size` был только у `Badge`, `tooltip_measure` —
локальный хак. Размеры задавались вручную (`add_fixed(w, 40)`), и виджет не мог
сказать контейнеру «мне нужно 137 px под этот текст».

Стало: `layout.v` + `layout_measure.v`, подробности —
в PROJECT.md, раздел «Layout: measure/arrange».

Сделано:

- [x] `measure(ctx) SizeHint` через опциональный интерфейс `Measurable` —
      интерфейс `Widget` не изменился, виджеты без `measure()` работают
      как раньше (запасной путь через `get_widget_bounds`)
- [x] двухпроходный layout: measure → arrange
- [x] `min`/`max` по каждой оси + политики растяжения `SizePolicy`
      (fixed / preferred / expanding)
- [x] параметры ребёнка `min`/`max`/`align` и `CrossAlign` (первая версия —
      `add_auto`/`add_ex`; заменены единым `add`, см. ниже)
- [x] `Window.fit_to_content` / `Dialog.fit_to_content`
- [x] `GridLayout.set_col_auto` / `set_row_auto`
- [x] проброс в C-ABI, Python-слой и YAML UI Builder
- [x] юнит-тесты `layout_test.v`
- [x] авто-размеры «как в современных фреймворках» (03.10.2026): один
      `add(w, flex:, min:, max:, align:)` вместо `add_fixed`/`add_auto`/
      `add_ex` и `Px`/`Flex`; растягиваемые виджеты растут от естественного
      размера; фиксированные поперёк не растягиваются; `Theme.control_height`;
      окна и диалоги по содержимому, `fit_min_size`; дорожки `GridLayout` по
      содержимому; флажок колеса `wheel`; примеры без фиксированных размеров

Осталось (перенесено в пункт 2):

- [x] `bounds` в самом интерфейсе — сделано как `Layouted` (`bounds_of`/
      `set_bounds`) в `widget_tree.v`, вместо ручных switch по kind
      в `get_widget_bounds`/`set_widget_bounds` (см. PROJECT.md, «Дерево
      виджетов»). Туда же переведены два устаревших switch в `tooltip.v`
      и `menu.v`
- [x] инфраструктура обхода иерархии — `HasChildren` (`child_widgets`),
      `HitTestable` (`hit_children`), `HasVisibility` + `walk_widgets` /
      `widget_at`, с потолком глубины 256 против циклов в дереве.
      **Потребителей пока нет**: доставка событий по-прежнему идёт
      старым путём (`handle_event` вниз по контейнерам), в C-ABI и
      Python эти функции не проброшены — см. незакрытый подпункт в
      пункте 2
- [ ] `parent` в интерфейсе — НЕ вводится, и это намеренно: указатель
      ребёнок→родитель вместе с существующим родитель→ребёнок дал бы цикл
      владения, который ломает якоря Boehm-GC в реестрах `*_capi.v`
      (см. vgui-capi/PROJECT.md, «Реестры объектов») — GC решил бы, что виджеты держат
      друг друга живыми, даже когда снаружи на них нет ссылок, и они бы
      никогда не собрались. Обход остаётся только сверху вниз, через
      `HasChildren`; кому нужен родитель (напр. закрыть диалог из его
      содержимого) — передаёт ссылку на него явно при построении дерева,
      а не читает её из виджета.

Это фундамент: без него не сделать ни адаптивную вёрстку, ни accessibility,
ни авто-размер окна под содержимое.

## 2. Дерево виджетов и инвалидация

Раньше кадр перерисовывался целиком (`mark_anim` глобально включал анимационный
режим, `SDL_Delay(16)`). Теперь, как у больших библиотек, работают dirty
regions: перерисовывается только изменившийся прямоугольник.

**Этап 1 (дерево виджетов) — ✅ сделано**, см. пункт 1 выше и PROJECT.md,
раздел «Дерево виджетов».

**Этап 2 (инвалидация и dirty regions) — ✅ сделано**, см. PROJECT.md, раздел
«Инвалидация и dirty regions». `DirtyRegion` + persistent render target у
`Window`, ветки `full`/`partial`/`skip_draw` в `render()`, `ctx.invalidate(r)` /
`invalidate_all()` / `mark_anim_rect()`, публичные `Window.invalidate(_all)` и
`Dialog.invalidate(_all)` в C-ABI и Python. Приложение в простое спит
(измерено: 0% ядра против 7% на трёх анимирующихся спиннерах). Осталось:

- [x] доставка событий по маршруту (27.10.2026, ветка `event-routing`):
      адресата находит окно (`widget_path_at` — тот же поиск, что у наведения),
      событие всплывает к корню, захват жеста, `mouse_enter`/`mouse_leave`,
      клик мимо снимает фокус в окне, клавиши — по фокус-учёту; контейнеры
      детям событий не раздают. PROJECT.md, «Доставка событий»; план —
      `docs/event_routing.md`
- [x] `invalidate(rect)` у виджета, накопление грязных областей — сделано
- [x] clip-стек в `RenderContext` — сделано (`push_clip`/`pop_clip`/`is_in_clip`,
      `clip_stack []Rect` в `render_context.v`/`sdl3_render.v`); виджеты уже
      клипуют своё содержимое через `push_clip(bounds)`/`pop_clip()`
- [x] кэш отрисовки в текстуру — **не делаем** (27.10.2026, по замерам): тяжёлым
      MarkdownView делали две ошибки — перевёрстка всего документа на каждом
      полном кадре (`set_bounds` ставил dirty) и вечный цикл разбора на абзаце
      с « | »; после их исправления полный кадр 1200×900 с PROJECT.md — 32 мс,
      таблица на 10 000 строк — 25 мс (отладочная сборка, программный рендер),
      а полные кадры бывают только по событиям. Кэш дал бы немного ценой
      отрисовки в текстуру со смещением координат и риска устаревшей картинки
- [x] инвалидация в сеттерах виджетов (27.10.2026): публичные `set_*` (~150)
      зовут `widget_changed()` — окна перерисуются на ближайшем кадре; внутри
      отрисовки и раскладки — тихо. PROJECT.md, «Инвалидация и dirty regions»
- [x] раздельная отрисовка нескольких областей за кадр (27.10.2026):
      далёкие грязные прямоугольники рисуются отдельными проходами
      (`DirtyRegion.passes`), близкие сливаются

## 3. Ввод текста для не-латиницы

`SDL_StartTextInput` вызывается (`sdl3_window.v:300`), но `SDL_TEXTEDITING`
не обрабатывается вообще. IME-ввод (китайский, японский, корейский) не работает —
нет отображения composition-строки.

- [ ] обработка `SDL_TEXTEDITING`, отрисовка composition-строки

## 4. Доступность (accessibility)

Отсутствует полностью. Ни a11y-дерева, ни ролей, ни экранных дикторов.
Qt/GTK/WPF интегрированы с UIA (Windows), AT-SPI (Linux), NSAccessibility (macOS).
Из-за этого GUI-библиотеку не берут в госсектор и корпоративный софт.

- [ ] экспорт дерева ролей / имён / состояний
- [ ] полная навигация с клавиатуры без мыши
- [ ] интеграция с платформенными API (UIA / AT-SPI)
